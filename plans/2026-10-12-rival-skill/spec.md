# One `/rival` skill; models chosen in the TUI

**Date:** 2026-10-12
**Scope:** /wrk/dev/rival, branch `feat/rival-skill` from master `d5b6c66` (v5.2.0, Rival.app removed).
**Status:** approved (fullsend; Codex plan review below)
**Release:** v6.0.0 (skills are removed: breaking), published from the Air, installed on the Dell.

## TL;DR

- One skill, `rival`, for both hosts. No model name in any skill name or skill text.
- Claude Code's `/rival` runs the model set for Claude Code (default **Sol 6.1**). Codex's `$rival` runs the model set for Codex (default **Opus 5.5**). So by default each host gets a review from the other vendor.
- The user picks both models in the TUI config window (`rival config`, Models), or with `rival config set skill.claude <model>` / `skill.codex <model>`.
- `/rival security [scope]` runs the security review (its model is still `security.reviewer`).
- All model skills go: `rival-codex`, `rival-sol`, `rival-claude`, `rival-fable`, `rival-k3`, `rival-grok`, `rival-security`. Install and update delete them.
- `ultrafast.codex` and `ultrafast.sol` default to **on**.
- The TUI config window loses the PLAN column and the plan toggles. `plan.models` and `rival command plan -m` stay for the CLI.

## Decisions (stated assumptions)

1. **Command:** `rival command skill --host claude|codex` reads the args like every `rival command <model>`, resolves the model from `skill.<host>`, and runs that model's spec through the existing `run_model_command`. Args that start with `security` go to the security review flow instead (`rival command security`, scope = the rest).
2. **Config keys:** `skill.claude` and `skill.codex`. Values: `codex`, `sol`, `claude` (or `opus`), `fable`, `k3`, `grok`. Defaults: `skill.claude = sol`, `skill.codex = claude`. A bad value is a config error naming the key. `rival config show` lists both with `default`/`file`.
3. **Usage text** names no model: `/rival 'prompt'`, `/rival review [scope]`, `/rival -re high review`, `/rival security [scope]`. The run's output still names the model that ran (the review header `Model: sol (gpt-6.1-sol)`); hiding it from skills, not from results.
4. **Efforts:** `-re` works as before; omitted effort uses `efforts.<model>` of the resolved model.
5. **Ultrafast default on.** A missing `ultrafast.<model>` key reads as true. `config show` shows `true default`. An account without Ultrafast gets the existing notice on every run; that is accepted.
6. **TUI scope ("refactor tui"):** the config window only. Models section = model table (MODEL, RUNTIME, ROUTE, EFFORT) + `/rival in Claude Code` and `/rival in Codex` pickers + the Ultrafast toggles. The PLAN column, its toggle key and hint go. No other TUI change.
7. **CLI keeps** `rival command codex|sol|claude|fable|k3|grok|security|plan` and `rival run`. Only the skills change.
8. **Codex skill** is generated by `skills::codex_skill("rival")` with `{{COMMAND}}` = `skill --host codex`; the Claude skill is `skills/rival/SKILL.md` with `rival command skill --host claude`.

## Risks

- ⚠ Users lose `/rival-codex` etc. muscle memory; install deletes them. Breaking → major version.
- ⚠ Default Ultrafast on: every Codex-runtime run on an account without Ultrafast prints the not-applied notice.
- ⚠ A model whose runtime is missing (e.g. Codex CLI not installed on a Claude-only machine) fails at preflight with the existing error; the message should name the config key to change. (R3 adds: on preflight failure from `skill`, append `set another model: rival config set skill.<host> <model>`.)

## Amendment (user, 2026-10-12): speed tier instead of an Ultrafast switch

Ultrafast is only on the Pro $500 plan (or Enterprise/Edu with it on); the $200 plan has the Fast tier only. So:

- `speed.codex` / `speed.sol` = `normal | fast | ultrafast`, default **fast** (assumption: the user wants speed by default, and Fast works on their plan; it uses more of the plan's quota).
- `fast` → `-c service_tier="fast" -c features.fast_mode=true` (Codex maps it to `priority`; checked live on 0.162.1, no warning). `ultrafast` → the existing pairs. `normal` → no tier args.
- Old `ultrafast.<model>: true` reads as `ultrafast` when `speed.<model>` is absent.
- Choosing `ultrafast` (TUI picker or `rival config set`) shows: "Ultrafast needs the Pro $500 plan (or Enterprise/Edu with Ultrafast on); other plans run at the standard tier."
- The omitted-tier notice and `config check` tags are tier-neutral; the plan line shows for ultrafast only.
